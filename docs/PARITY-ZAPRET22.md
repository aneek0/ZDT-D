# ZDT-D vs Zapret 2 GUI 22.0.0.0 — паритет функционала

Дата: 2026-11-01. Источник требований: [Zapret 22.0.0.0 changelog](https://jzesawgjsz.zapret.moe/Zapret/zapret-22-stable-october-2026).
Сравнение только по трём областям: движок zapret2 (пресеты/профили/фейки), подбор стратегий, BlockCheck.
Платформы разные: Zapret 22 — Windows GUI над winws2 (WinDivert), ZDT-D — Android-модуль над nfqws2 (NFQUEUE, тот же upstream-проект zapret2). Всё про ZDT-D проверено по коду репозитория.

Сводный вердикт: **~60–70% паритета**. Движок — высокий, подбор — средний, BlockCheck — ниже среднего.

---

## 1. BlockCheck

ZDT-D разбивает это на два инструмента: **nfqws-tester** (подбор стратегий, стратегие-центричен) и **dpi-detector** (диагностика «почему сломано»), разные экраны (`BlockcheckScreen.kt` / `DpiDetectorScreen.kt`).

| Возможность | Zapret 22 | ZDT-D | Паритет |
|---|---|---|---|
| Открывает сайты «как Chrome» (ClientHello, HTTP/2) | Да | Нет — curl с системным TLS и Chrome-UA (`nfqws-tester/src/main.rs:915`); dpi-detector — свой TLS 1.2+1.3+HTTP+HTTPS стек | ❌ |

Нет: замедление по SNI, «сайт лежит сам», hosts | 🟡 |
| Место фильтра (узел на пути) | Да | Нет — traceroute/hop-логики нет ни в одном крейте | ❌ |
| Как работает фильтр (дробления, ECH, белые имена) | Да | Частично: whitelist-SNI пробы в dpi-detector (`tcp16.json`, Hetzner/Cloudflare/CDN77). ECH/дробления — нет | 🟡 |

## 2. Подбор стратегий

| Возможность | Zapret 22 | ZDT-D | Паритет |
|---|---|---|---|
| Каталог кандидатов | Перебор приёмов | Портированные каталоги zapretgui: `strategic/scan/{tcp,udp,voice}.txt` (3840/633/574 строки, ≈450–500 TCP-кандидатов) + fallback на пресеты | ✅ |
| «Работает» = данные реально прошли | Порог объёма, медленный сервер ≠ удача | Код ≠ 400, 2xx ≥128 байт (заглушка-200 не проходит); обрыв = провал | ✅ |
| Подтверждение повторами | 3 успеха, одна «тишина» прощается (до 4 попыток) | 3 успеха; одна «тишина» (timeout/unreachable) прощается, явный сбой DPI стоп; + baseline/pass-control/post-success | ✅ |
| Ранний стоп на первой надёжной + «соседи» | Да | Нет — весь батч до конца; память падений 14 дней | 🟡 |
| «Применить» → профиль сайта, общий не трогает | Да | Частично: экспорт пресета + глобальная инъекция выбора хостлиста (`api.rs:1106`); per-item API есть, но скан его не использует | 🟡 |
| Поиск «белых» SNI для фейков | Да | Нет — только захардкоженные имена в каталоге | ❌ |
| Фолбэк HTTP↔HTTPS / авто-QUIC | Да | Нет автоперехода; UDP-каталоги выбираются вручную | ❌ |
| Продолжить прерванный | Да | Нет resume; есть «skip tested» (`--skip-confirmed`) | 🟡 |
| Проверка после «Применить» настоящим браузером | Да (headless Edge/Chrome) | Нет | ❌ |

## Топ-5 гэпов по влиянию

1. **Браузерная проба** (Chrome ClientHello + HTTP/2 вместо curl) — бьёт по BlockCheck и подбору: фильтр может резать пробу и пропускать браузер, и наоборот.
2. **QUIC-пробы + автопереход на QUIC-стратегии**, когда TCP открыт, а UDP 443 режут.
3. **Apply → per-item профиль сайта.** Инфраструктура (`items` API + cutover) уже в репо — скан просто её не использует.
4. **Критерий успеха по объёму + ранний стоп + соседи** удачной стратегии.
5. **Soft-reload списков** без рестарта nfqws2.

Сильные стороны ZDT-D: per-app UID-привязка, Telegram DC download/upload-пробы, трёхфазный контроль скана, UDP-каталоги для игр и голоса.

## Статус закрытия (2026-11-01)

- **GAP-3 (применить → профиль сайта)** — закрыто. `Apply` из блока подбора для
  nfqws2+tcp_https больше не делает глобальную инъекцию: стратегия применяется
  как per-item профиль сайта через существующий daemon `items` API —
  существующий item на этом hostlist обновляется (повторное применение не плодит
  копии), иначе добавляется новый item `--name=<сайт>` + export-`item_lines` с
  `--hostlist=` сканируемого списка. Кастомный домен сначала сохраняется в
  `strategic/list/blockcheck_<домен>.txt`. Если преамбула профиля не объявляет
  blob'ы стратегии (daemon не умеет править преамбулу через item API) —
  откат на прежний глобальный apply. Тестер: `export` отдаёт `blob_names` +
  готовый `item_lines`, принимает `--hosts`.
- **GAP-4 (объём + ранний стоп + соседи)** — закрыто.
  1. Критерий «загрузилось»: `classify_https` теперь `empty_body` (Blocked) для
     2xx с телом < 128 байт (204 исключение) — «работает» = сайт загрузился,
     а не просто ответил.
  2. `--stop-on-first`: подбор останавливается на первой подтверждённой
     стратегии, затем досканивает «соседей» (тот же десync-техника из
     каталога) коротким батчем; остальное остаётся непроверенным.
  3. Оба флага — чипы в UI (`Остановить на первой удачной`, по умолчанию выкл;
     поведение существующих прогонов не меняется).
- **GAP-1 (браузерная проба)** — закрыто в двух частях.
  1. Проба curl говорит по HTTP/2 (ALPN как у браузера): `--http2`, возможность
     определяется один раз по `curl --version`; чип `Проба по HTTP/2`, по умолчанию выкл.
  2. Кнопка `Проверить в браузере` у удачной стратегии: применяется стратегия,
     затем первый просканированный хост загружается headless WebView — тем же
     Chromium-стеком, что и браузер устройства (системные TLS/DNS/h2). PASS =
     страница догрузилась без сетевой ошибки основного фрейма; FAIL = ошибка
     сети или таймаут. Это эквивалент zapret22 «после применения сайт
     открывается настоящим браузером» без покидания приложения.
- Остальные гэпы (QUIC, IPv6, место фильтра, «сайт лежит сам», soft-reload
  списков, white-SNI пресеты, Matrix/SimpleX) — не закрыты, см. таблицы выше.
